# Domain Model

## Core Entities

### User & Project
- **User:** The human operator interacting with the platform.
- **Project:** A contextual workspace grouping one or more Repositories and their analysis history.

### Repository & Versioning
- **Repository:** A Git repository registered under a Project. Currently read from a local path; GitHub connection comes later.
- **RepositorySnapshot:** Exactly one per (Repository, commit SHA). Identifies a frozen point in time and is `ready` or `failed`. `ready` means the exact Git commit has been successfully captured and its complete included ArtifactVersions/exclusion records have been persisted atomically; it does not imply structural analysis, embeddings or semantic indexing. All relationship and impact queries are strictly scoped to a ready Snapshot.

### Artifacts & Code
See [ADR: Snapshot Ingestion and Artifact Identity](decisions/snapshot-ingestion.md).
- **Artifact:** The logical repository object, identified by (`repository_id`, `git_repository_path`) and stable across snapshots. `git_repository_path` is the repository-relative path exactly as represented in Git's tree: `/` separators, no OS-specific path normalization, no case folding, no further canonicalization (stored in the `artifact.path` column). A rename creates a new Artifact; rename continuity is future work. Has a kind (`code`, `document`, `config`).
- **ArtifactVersion:** An Artifact as it exists in one Snapshot: (`artifact_id`, `snapshot_id`, `content_sha256`, `git_blob_sha`). The same path has a distinct version in every snapshot that contains it.
- **Content:** Immutable normalized text identified by its SHA-256. Shared by every version (across paths, snapshots and repositories) with identical content.
- **CodeEntity:** A strongly-typed projection of an Artifact produced by the `Code-Analysis` module (e.g., an exported function, a class).

### Retrieval & Analysis
- **Change:** The trigger input for an analysis (e.g., a Diff, a Pull Request, or a specific commit).
- **Relationship:** A directed edge between two Artifacts (e.g., `imports`, `historically_co_changed`). Tagged with a temporal validity window (valid at Snapshot X).
- **Embedding:** The mathematical vector representation of an Artifact or a chunk of an Artifact, utilized by the semantic retrieval subsystem.

### Impact & Evidence
- **Evidence:** A first-class, materialized object generated post-retrieval. Contains the explicit rationale (AST snippet, lexical match count, semantic similarity score) supporting why a candidate was retrieved.
- **Analysis:** The final, grounded impact report generated by the Reasoning module, combining the Change context, Evidence objects, and LLM inferences.

### Operations
- **IngestionJob** *(planned, not implemented)*: Would track the state machine of multi-stage ingestion (e.g., Queued, Extracting, Parsing, Embedding, Complete, Failed). Current snapshot capture has no job entity; see [data-lifecycle.md](data-lifecycle.md).
